# ProfiBux

Telegram Mini App + бот для выполнения рекламных заданий (CPA/affiliate).
Пользователи берут офферы, выполняют условия, загружают доказательства
и получают вознаграждение на баланс с выводом в рублях или USDT.

## Что уже работает

Это не макет: в репозитории лежит рабочий срез продукта с реальной БД,
транзакционным учётом денег и полным циклом от каталога до выплаты.

**Mini App**
- Каталог заданий: фильтры по сумме, сложности, категории, сортировка, поиск
- Карточка задания: пошаговая инструкция, требования к доказательствам, лимиты
- Взятие задания со снапшотом награды и таймером выполнения
- Загрузка доказательств: фото (с клиентским сжатием), видео, комментарий
- Полная цепочка статусов: ожидает подтверждения → ожидает выплаты → выплачено / отклонено
- «Мои задания» с табами и таймлайном каждого выполнения
- Профиль: три состояния баланса раздельно, история операций из леджера
- Вывод: карта, СБП, USDT (TRC-20 / TON) с расчётом комиссии и фиксацией курса
- Уведомления: колокольчик с бейджем, история, группировка по дням
- Рефералы: ссылка, QR-шаринг, два уровня, график заработка

**Админ-панель**
- Дашборд: очередь модерации, нарушения SLA, заявки на выплату, расхождение заявленного и фактического времени одобрения
- Офферы: создание и редактирование карточки, публикация, статусы, **ручное переопределение сложности и времени одобрения**
- Модерация: приоритизированная очередь, лок за модератором, горячие клавиши, три исхода (одобрить / доработка / отклонить)
- Выплаты: очередь, антифрод-флаги, одобрение, отметка отправки с TX, отказ с возвратом средств
- Пользователи: поиск, статистика, ручная корректировка баланса, смена статуса

**Бот и воркеры**
- `/start` с реферальными deep-link, `/balance`, `/tasks`, `/support`
- Воркеры: снятие холда, автоодобрение, истечение сроков, снятие локов, пересчёт статистики, сверка леджера, outbox-доставка

## Стек

- **Next.js 16** (App Router, RSC, Server Actions) + **React 19** + **TypeScript**
- **Tailwind CSS v4** + компоненты в стиле shadcn/ui (Radix)
- **PostgreSQL 16** + **Prisma**
- **grammY** — Telegram-бот (отдельный процесс)
- Воркеры на интервалах (без отдельной очереди Redis)
- Доказательства пишутся на диск (`.uploads`); S3 можно подключить позже

## Запуск локально

Нужен только **Node.js 20+** и **PostgreSQL** (или Docker).
Telegram, S3 и Redis для локального просмотра не требуются.

```bash
npm install
npm run setup
npm run dev
```

- Mini App — http://localhost:43117
- Админ-панель — http://localhost:43117/admin
- Баннеры в шапке — http://localhost:43117/admin/banners

`npm run setup` делает всё сам: создаёт `.env` со сгенерированными секретами,
проверяет PostgreSQL (при отсутствии поднимает контейнер из
`docker-compose.yml`), создаёт роль и базу, если их нет, накатывает схему
и заливает демо-данные. Скрипт идемпотентен — повторный запуск ничего
не ломает и не перезатирает существующий `.env`.

### Почему `npm run dev` кажется медленным

Это нормально и **не лечится «просто сервером с тем же `dev`»**.

`next dev` компилирует каждый роут при первом заходе, отдаёт огромный
неминифицированный JS и отключает большинство прод-оптимизаций. В Telegram
WebView к этому добавляется `telegram-web-app.js` и туннель (ngrok).

Живой запуск:

```bash
npm run build
npm run start
```

На VPS рядом с PostgreSQL это обычно быстрее в разы: бандлы уже собраны,
каталог кэшируется на 20 с, вкладки дока префетчатся. `npm run dev` на
сервере останется таким же тяжёлым, как на ноутбуке.

Не коммитьте `.env` — секреты и ключи сетей туда не входят.

Сиды создают 13 офферов из четырёх источников, шесть пользователей,
выполнения на всех стадиях жизненного цикла, доказательства с картинками,
флаги антифрода, реферальное дерево, заявку на вывод, уведомления
и три промо-баннера в шапке Mini App.

### Если PostgreSQL ещё не установлен

Проще всего через Docker — тогда `npm run setup` поднимет базу сам:

```bash
docker compose up -d
```

Либо нативно:

```bash
# macOS
brew install postgresql@16 && brew services start postgresql@16

# Ubuntu / Debian
sudo apt install postgresql && sudo systemctl start postgresql

# Windows — установщик с postgresql.org/download/windows
```

Если PostgreSQL у вас уже есть со своими логином и паролем — просто
поправьте `DATABASE_URL` в `.env` и запустите `npm run setup` снова.

### Воркеры и бот

На живом запуске оба процесса нужны: без воркеров холд не снимется и
бот не доставит отказ/выплату. Деньги воркеры трогают только через
общий код приложения, не своей записью в кошелёк.

```bash
npm run workers            # постоянно, в отдельном терминале
npm run workers -- --once  # один прогон и выход
```

Бот требует токен от [@BotFather](https://t.me/BotFather) в `TELEGRAM_BOT_TOKEN`:

```bash
npm run bot
```

## Перед ручным запуском

Старт — без сетей и автокрипты. Вы модерируете и платите руками.

1. `DEV_AUTH_BYPASS=false`
2. Живые `TELEGRAM_BOT_TOKEN`, `AUTH_SECRET`, `PAYOUT_ENCRYPTION_KEY` (64 hex)
3. `MINIAPP_URL` — публичный HTTPS, тот же что в BotFather
4. `SUPPORT_TELEGRAM_USERNAME` — живой аккаунт, не заглушка
5. Три процесса: `npm run start`, `npm run workers`, `npm run bot`
6. Задания — «Админка → Офферы → Новое задание», статус «Активен»
7. Выплаты — «Админка → Выплаты»: одобрить → отправить с референсом → подтвердить
8. `npm run check:e2e` перед выкладкой

Для деплоя удобен `output: "standalone"`: после `npm run build` можно
запускать `node .next/standalone/server.js` (скопировав `.next/static`
и `public` рядом, как в документации Next.js).

Оферту и политику ПДн добавляем отдельно, в конце.

## Для бэкенд-разработчика

Коротко, что нельзя ломать и что ещё не сделано.

**Деньги.** Истина — append-only `ledger_entries`. `wallets` — кэш в той же
транзакции. У каждого движения `idempotencyKey`. Подробности — раздел
«Что важно знать о деньгах» ниже и [docs/02-database.md](docs/02-database.md).

**Сессия Mini App.** HMAC-cookie `pb_session`, проверка Telegram `initData`.
`DEV_AUTH_BYPASS` только локально.

**Касса.** Один воркер-процесс, код в `src/server/modules/jobs.ts`.
Не пишите в `wallets` из бота или скриптов в обход модулей.

**Ещё не закрыто (можно брать в работу):**
- папки `prisma/migrations` нет — схема накатывается `db push`, для прода
  лучше завести миграции;
- доказательства на диске (`.uploads`), S3 не подключён;
- оферта / политика ПДн не свёрстаны;
- CI нет, проверка — `npm run check:e2e` и `npm run typecheck`.

Документы: [`docs/`](docs/). Сквозные инварианты денег гоняет e2e.

## Подключение к Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в `.env`.
   Кнопка «Поддержка» в профиле открывает `SUPPORT_TELEGRAM_USERNAME`
   (по умолчанию `profibux_support`).
3. Поднимите публичный HTTPS-адрес (для разработки — `ngrok http 43117`)
   и укажите его в `MINIAPP_URL`.
4. В BotFather: `/newapp` → выберите бота → задайте URL Mini App.
5. Поставьте `DEV_AUTH_BYPASS=false` — вход пойдёт через проверку подписи
   `initData`.

### `npm run check:e2e`

Исполняемая версия критериев приёмки из
[docs/05-tech-spec.md](docs/05-tech-spec.md). Проверяет не интерфейс, а то,
что дороже всего сломать незаметно:

- награда фиксируется снапшотом — снижение ставки в оффере не задевает
  уже начатые выполнения;
- повторное и параллельное одобрение не удваивают начисление;
- холд снимается корректно, реферальный бонус начисляется ровно один раз;
- заявка на вывод замораживает средства, отказ возвращает их, повторный
  отказ не удваивает возврат;
- списание не может увести баланс в минус;
- `SUM(ledger)` сходится с кэшем в `wallets`;
- **синхронизация из партнёрской сети не перезаписывает поля, которые
  админ выставил вручную** — сложность и время одобрения;
- важные уведомления дублируются в бот, рутинные — нет.

Работает на отдельной базе (`<имя>_e2e`), которую создаёт и удаляет сам,
поэтому демо-данные не трогает и запускать можно сколько угодно раз.

## Что важно знать о деньгах

Три правила, которые нельзя нарушать при доработках:

1. **`ledger_entries` — append-only.** Никаких `UPDATE`/`DELETE`. Ошибка
   исправляется записью типа `REVERSAL`.
2. **`wallets` — кэш, а не истина.** Истина — сумма по леджеру. Меняются
   только внутри той же транзакции, что и вставка записи.
3. **Каждое движение денег имеет `idempotencyKey`.** Уникальный индекс
   физически исключает двойное начисление при ретраях и постбеках.

Воркер `ledger-reconcile` сверяет кэш с леджером; расхождение — инцидент
первого приоритета.
